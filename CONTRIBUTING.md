# Участие в разработке

Спасибо, что хотите помочь! Проект небольшой, правил немного.

## Быстрый старт

```bash
git clone https://github.com/turpentieqe/builder-apk.git
cd builder-apk
python3 tests/run.py        # 57 тестов, SDK не нужен
```

Зависимостей нет — только `python3` (>= 3.9) и стандартная библиотека.
Android SDK нужен лишь для проверки `build`/`inspect` вручную.

## Что приветствуется

- Новые сценарии `doctor` (ещё один способ сломаться в Termux)
- Поддержка других языков (`--lang`) — пока только Kotlin и Java
- Точнее подсказки в ошибках: сообщение должно говорить, **что делать**
- Тесты на реальные выводы инструментов (aapt/apksigner меняют формат между версиями)

## Что не принимаем

- Переписывание на Gradle / обёртки над Gradle
- Внешние зависимости (requests, Pillow, click). Всё на стандартной библиотеке.
- Правки без теста, если меняется поведение стадии

## Стиль кода

- Python 3.9+, без нового синтаксиса
- Имена и docstrings — по-русски, как в проекте
- Каждая стадия сборки бросает `BuildError(stage, message)`, а не голый `Exception`
- Всё, что может упасть молча, обязано попасть в `warnings`

## Как предложить изменение

1. Форкните репозиторий и создайте ветку: `git checkout -b fix/doctor-arch-hint`
2. Напишите падающий тест (`tests/`), затем код
3. `python3 tests/run.py` — всё зелёное
4. PR с описанием: что было, что стало, почему

## Сообщить об ошибке

Откройте Issue по шаблону — он попросит `builder-apk doctor --json` и полный
вывод упавшей команды. Без этого почти невозможно понять, что случилось.
